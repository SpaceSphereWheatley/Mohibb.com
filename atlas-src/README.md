# Atlas — F1 post-race engineering dashboard

A browser-based post-race analysis dashboard for Formula 1, served at
**`mohibb.com/atlas/`**. Distance-synchronised telemetry, fuel-corrected stint
degradation, cumulative race traces, corner decomposition and a pit-execution
audit — all computed in the browser. There is no backend.

This directory is the **source**. The built site is emitted to `../atlas/`,
which is what the repository publishes.

---

## ⚠ Deploy requires one Cloudflare Pages change

Unlike everything else in this repository, Atlas has a build step. Until the
Pages project is given a build command, `mohibb.com/atlas/` will 404.

In the Cloudflare Pages project settings:

| Setting | Value |
| --- | --- |
| Build command | `npm --prefix atlas-src ci && npm --prefix atlas-src run build` |
| Build output directory | `/` *(unchanged)* |
| Node version | 22 *(picked up from the root `.node-version`)* |

The output directory deliberately stays `/`. `npm run build` runs
`next build` and then copies the export into `../atlas/`, so Pages still
publishes the repository root and every other page on the site is unaffected.
`/atlas/` is in `.gitignore` — it is generated at deploy time, never committed.

## Running it locally

```bash
cd atlas-src
npm install
npm run dev        # http://localhost:3000/atlas/
```

Production build, exactly as Pages runs it:

```bash
npm run build      # next build → ./out → ../atlas
npx serve ..       # then open http://localhost:3000/atlas/
```

Other scripts: `npm run typecheck`, `npm run sample` (regenerates the sample
dataset).

## Stack

| Concern | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router) with `output: "export"`, `basePath: "/atlas"` |
| Language | TypeScript, `strict` |
| Styling | Tailwind CSS v4 — tokens live in `@theme` in `src/app/globals.css` |
| Grid | `react-grid-layout` v2 (`useContainerWidth` + `ResponsiveGridLayout`) |
| High-frequency charts | uPlot — the telemetry strips, ~5 000 points per channel |
| Statistical charts | ECharts (canvas) via `echarts-for-react`, tree-shaken imports |
| State | Zustand, with `persist` for layout and selections |
| Heavy maths | a shared Web Worker, with an inline fallback |

`lib/compute.ts` is the single implementation of the maths. The worker is a
thin dispatcher over it and `useDataWorker` falls back to calling it directly
when a `Worker` cannot be constructed, so there is never a second copy of a
model to keep in sync.

## Data

**OpenF1** (`api.openf1.org`) is the default source: pick a season and a
session in the loader. Lap, stint, pit, interval, position and race-control
data are fetched up front; car telemetry is fetched **per lap, on demand**, and
resampled laps are cached in IndexedDB (`atlas-telemetry`).

Two things OpenF1 does not publish, and the UI says so rather than inventing
them:

- **Steering angle** — the channel is omitted from the strip stack entirely
  when the source is silent.
- **Stationary (wheel-change) time** — the pit audit shows `n/p` and reports
  total pit-lane duration instead.

**File import** covers both. Drop a `.json` in the interchange shape
(`{ meta, drivers[], laps[], stints[], pits[], zones[], telemetry[] }`) or a
`.csv` of one lap's telemetry with at least a time and a speed column. Every
field goes through a normaliser, so a partial file loses the fields it is
missing rather than failing to load.

`public/data/sample-session.json` is a **synthetic** 57-lap race on a fictional
circuit, generated by `scripts/make-sample.mjs`. It exists so the dashboard has
something to draw with no network, and is labelled as synthetic in the file
itself.

## The models

**Distance interpolation.** Telemetry cannot be correlated on elapsed time, so
every lap is resampled onto a uniform 1 m grid: distance is recovered by
trapezoidal integration of the speed trace, rescaled to the known lap length,
and every channel is linearly interpolated onto it. Elapsed time comes along
for the ride, which makes the delta trace a pointwise subtraction rather than a
second integration. Gear is snapped back to integers — interpolating a discrete
channel produces values that never existed.

**Delta time.** `Δt(d) = t_C(d) − t_R(d)`. Rising means the comparison car is
losing time.

**Fuel correction.** Fuel on board at lap *i* of *N* is proportional to `N − i`,
so the time it costs is `(N − i)·β`. Correcting to an empty-tank reference
therefore **subtracts** that term:

```
T_corrected(i) = T_raw(i) − (N − i)·β
```

β defaults to 0.035 s per lap of fuel. (A `reference: "full"` option adds the
term instead — same gradient, different intercept.)

**Stint degradation.** Corrected lap times are regressed against tyre age
within each stint by ordinary least squares, with one robust pass that drops
residuals beyond 2.5σ. Laps are excluded when they are lap 1, an in-lap or
out-lap, run under SC/VSC/red, within 1.2 s of the car ahead, or more than 7 %
off the driver's own best. Rejected laps are kept and can be drawn greyed out —
seeing what the model threw away matters.

**Corner detection.** Apexes are local minima in smoothed speed with enough
prominence either side to be corners rather than lifts, found on the reference
lap and then re-measured on the comparison lap over the *same* stretch of
track. No circuit geometry is needed, so it works on imported data too.

## Notes

- Every numeral is `tabular-nums`; telemetry readouts are written straight to
  the DOM from a rAF loop rather than through React state, so scrubbing does
  not re-render the panel.
- Panel positions, the active widget set and the lock are persisted to
  `localStorage` under `atlas-dashboard-v1`; driver selections under
  `atlas-session-v1`.
- CI does not cover this directory's CSS (Tailwind at-rules) or the built HTML.
  `npm run typecheck` and `npm run build` are the checks that matter here.
